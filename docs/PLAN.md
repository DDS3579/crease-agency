# Crease — Phase 0 plan

## Stack decision

Static HTML generated from typed content, built with Vite + TypeScript strict + vanilla ES modules, plain CSS, pnpm. No framework.

Why not Next.js: this is one static route, no data fetching, no hydration, no server state. Next would add a runtime/router/hydration payload and server/edge complexity without buying anything. The only interactive system is a scroll-scrubbed WebGL2 stage; every kilobyte and millisecond should go to the sheet, not to a component runtime.

Renderer choice: raw WebGL2, not ogl. The scene is one subdivided sheet, one baked shadow plane, a small uniform fold array, and two custom shaders. There is no scene graph, camera controls, material system, loaders, or math library need large enough to justify a wrapper. Raw WebGL2 keeps the scene chunk small and makes the GPU parity / resource-count tests direct. `scripts/engine-choice.ts` records the measured byte comparison used for this decision.

Versions are checked from the npm registry at build time, not pinned from memory. The harness targets Node >= 22.19 because current Vitest / sharp / Lighthouse CI require it.

## Tokens

Use the supplied `:root` exactly. Single light theme. No UI gradients, shadows, glass, grain. Accent `--crease` only for moving creases and progress rail. Focus rings ink. Fluid type scale as specified. 12-col grid, max 1440, `--pad`.

## Module list

Pure / unit-tested:
- `folds`: tree membership, leaf-to-root composition, soft bend band, `applyFolds`, normals, isometry.
- `journey`: `stateAt(P)`, ramp staggering, shortest-arc azimuth, dwell drift, launch ink fade.
- `print`: layer layout rectangles, pure draw instructions.
- `crease-pattern`: seeded deterministic SVG from fold primitives.
- `tier`: capability gate + ladder decision.
- `exposure`: paper calibration + WCAG contrast checks.

Runtime:
- `ticker`: one prioritized rAF loop, sleeps idle, pauses hidden/offscreen.
- `spring`: critically damped scroll scalar.
- `renderer`: WebGL2 resources, on-demand render, debug counts, context loss, downgrade dispose.
- `print-texture`: generated once after fonts ready, channel-packed RGB, mipmaps/anisotropy.
- `ui`: nav hairline, reveals, rail, form, CTA focus.

## Fold-tree contract

Sheet space: x [-1,1], y [-0.625,0.625], z=0 flat. Printed face +z. Positive angle = valley (moving side toward +z). Negative = mountain.

Each fold: `{ id, axisPoint:[x,y], axisDir:[x,y], parent:string|null, angle:number }`.
Moving side is the half-plane pointed to by `rotate90(axisDir)` (left normal of axis direction). A vertex is affected by a fold only if it is on that fold's moving side and on the moving side of every ancestor.

Seed tree:
- `f1` hinge: axisPoint [0,0], axisDir [1,0], parent null. Moves top half.
- `f2` top-left corner: child of f1. Diagonal axis cutting 0.45 from top-left corner.
- `f3` top-right corner: child of f1. Diagonal axis cutting 0.45 from top-right corner.
- `f4` lip: root, axisPoint [0,-0.44], axisDir [-1,0] so moving side is bottom strip. Disjoint from f1 region.
- `curl` reserved virtual fold: root, nearest free corner, max 14deg, hero only.

Composition: leaf-to-root. Each fold rotates about its own flat-space axis. Child regions are inside parent regions, so this is exact. Soft crease: cylindrical bend band width 0.04 centered on axis, arc-length preserving. Normals rotate analytically. Layer epsilon along normal proportional to tree depth.

CPU `applyFolds(point, foldState)` is source of truth. GPU vertex shader implements the same math. Parity target: 64 samples, float render target, max abs error <= 1e-4.

Segments: hero 100svh dwell; four chapters 150svh (100 dwell + 50 ramp). Offsets measured from panel geometry via ResizeObserver after fonts.ready. P in [0,1] over journey. Spring stiffness 120 damping 30. Ramps: changed folds in id order, each 55% of ramp, staggered over remaining 45%; single changed fold uses whole ramp. easeInOutCubic per fold. Ink/camera interpolate whole ramp. Azimuth shortest arc. Dwell drift <= ±2deg scroll-driven.

Launch: cover-fit top-down computed from viewport aspect. Ink fades 1->0 over last 30% of unfold. Exposure calibrated so flat top-down front face equals `--paper` within 2/channel. Canvas fades once; following DOM is same paper colour.

## Render budget plan

Tier A: one sheet mesh 128x80 = 20,480 triangles; shadow plane 2 triangles; total 20,482 <= 25k. Draw calls: shadow + sheet = 2 <= 3. Textures: print RGB 2048x1280 + optional 1x1 fallback = <=3. GPU memory estimate: print ~7.5MB + mip ~10MB, mesh <1MB, shadow <0.1MB, buffers small => <32MB. DPR <=1.75, MSAA. JS sim+draw target <=3ms/frame; measured in harness. On-demand render only: P epsilon, curl animating, resize, quality. Idle zero renders.

Tier B: 64x40 = 5,120 triangles, DPR <=1.25, no MSAA/fibre/curl. Poster-swap: no canvas, five posters crossfade by chapter, same sticky geometry.

Runtime ladder: rolling p75 over 30 moving frames. >20ms step down once, never up: A0 -> A1 (DPR1.25, fibre off, curl off) -> A2 (scale .75, 64x40) -> poster. Context lost: try restore, else poster. Dispose all GPU resources on teardown/downgrade.

## Tier matrix

| condition | mode/tier |
|---|---|
| JS + WebGL2 API + !saveData | stage |
| no JS / saveData / no WebGL2 API | stacked |
| stage + desktop + fine pointer + good hw | A |
| coarse / width<768 / mem<=4 / cores<=4 | B |
| context fail / unrecoverable / ladder bottom | poster-swap |
| prefers-reduced-motion | no scrub/curl/drift/glow; IO jumps keyframes; plain fades |

## Risks

1. GPU/CPU fold parity with soft bend band: mitigate with exact arc-length math and float-target parity test.
2. Launch seam: mitigate with exposure calibration, cover-fit, pixel test, single opacity fade.
3. LCP/CLS with fonts/poster: mitigate with server HTML, explicit media dimensions, media preload, size-adjusted fallbacks, idle canvas.
4. Text/object separation: frustum offset + compact shadow + pixel-under-text test.
5. Software CI cannot prove real-device 60fps: report UNVERIFIED; guarantee ladder + on-demand rendering.
6. Missing [FILL] fields: omit gracefully, dev-only warning, no dead links. Form falls back to mailto if email present, else local demo validation with clear status.

## Assumptions

- Domain, email, socials, form endpoint are [FILL] and omitted. No real clients/metrics/awards/testimonials/team names.
- Demo project sentences/stacks are invented only as demo copy and live in `src/content/demo/`.
- If a font family is unavailable, swap to Hanken Grotesk / Geist Mono and record. Current registry has all three families.
- Form with no endpoint/email completes as a local demo submission with an honest aria-live status; honeypot and validation still work.
